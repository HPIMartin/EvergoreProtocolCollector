| **C10** | **A request the server rejects on its own is neither counted nor logged** (falsifier finding 2026-08-05, re-measured 2026-08-14): the original case is **closed** — an invalid percent-escape such as `/overview%zz` does reach both filters and is counted (the earlier "Micronaut answers it ahead of the filter chain" reading was a misdiagnosis of the old filter dying on `request.getPath()`), pinned by `RateLimitFilterTest.countsAMalformedRequestTargetLikeAnyOther`. | **C11** | **Auth, session and rate-limiting rework around JWT** (author request 2026-08-14, one theme because the three parts only make sense together): (a) replace the `?token=` query credential with a **JWT**-based login/session, so no credential travels in a URL, a bookmark, or the browser history; (b) turn the rate limit from a reset window into a **token bucket** (burst carries one cold page load, a low sustained refill rate stops a scanner), so the limit can be strict again without throttling a normal user; (c) split what the audit trail must record from what it may drop: the interesting event is a **root request** (which overview or avatar an *authenticated* user opens), not the follow-up resources of a session that has already been identified. | **D18** | **Pre-group the recompute's aggregation in SQL instead of loading every row into the JVM** (author proposal 2026-09-03, measured the same day): the evaluator loads all of an avatar's entries as objects and values them one by one, so both memory and time grow linearly with the log forever, the OOM path once the ledgers outgrow the heap.
