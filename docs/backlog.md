| **D18** | **Pre-group the recompute's aggregation in SQL instead of loading every row into the JVM** (author proposal 2026-09-03, measured the same day): the evaluator loads all of an avatar's entries as objects and values them one by one, so both memory and time grow linearly with the log forever, the OOM path once the ledgers outgrow the heap. The valuation is **linear** in `quantity × quality`, so it factors exactly: `Σ storageValue(item) · quantity · quality/100 = storageValue(item)/100 · Σ(quantity · quality)`.
